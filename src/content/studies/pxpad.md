키보드와 마우스로 조작하고 싶은데, 대상 프로그램은 게임패드의 입력을 기대한다면 어떻게 연결할 수 있을까. PXPad는 이 문제를 Windows ARM64에서 풀기 위해 만든 개인 프로젝트다. PS Remote Play와 Xbox 클라우드를 대상으로, 키보드·마우스 입력을 각각 가상 DualSense와 Xbox 호환 패드 입력으로 바꾸는 것이 목표다. reWASD 설치나 구독에 의존하지 않는 앱으로 구성했다.

겉으로 보이는 기능은 키 매핑이지만, 구현은 버튼 이름을 바꾸는 데서 끝나지 않는다. Windows가 인식할 가상 장치를 연결해야 하고, 마우스의 움직임을 스틱의 기울기로 바꿔야 한다. 사용자가 다른 창으로 이동하거나 입력을 보내던 프로세스가 멈췄을 때, 마지막 입력이 계속 남지 않도록 처리하는 것도 필요하다.

이 글에서는 PXPad 0.4.0에 구현한 흐름을 따라가며 이 문제들을 어떻게 나누어 다뤘는지 정리한다.

## 키 매핑과 가상 장치 사이에 필요한 것

키보드에서 W가 눌렸다는 사실을 알아내는 것과, 대상 앱이 게임패드의 왼쪽 스틱이 앞으로 기울었다고 인식하는 것은 서로 다른 단계다. PXPad에서는 입력을 수집하고 매핑하는 부분과 가상 컨트롤러를 제공하는 부분을 분리했다.

사용자 화면과 Windows 입력 처리는 C#/.NET 10 WPF가 맡는다. 여기서 키 상태와 마우스 이동을 모아 스틱·버튼·트리거의 공통 상태로 만든다. Go 백엔드는 이 상태를 받아 VIIPER 기반 가상 컨트롤러에 전달한다. USB/IP와 Windows 드라이버가 가상 장치를 연결하는 경로를 담당한다.

```text
키보드·마우스의 입력
        ↓
WPF 앱: 입력 수집과 매핑
        ↓
스틱·버튼·트리거 상태
        ↓
Go 백엔드: 컨트롤러별 출력 변환
        ↓
USB/IP로 연결한 가상 패드
```

여기서 USB/IP를 쓴다고 외부 서버가 필요한 것은 아니다. PXPad의 백엔드는 같은 PC의 루프백 주소에서 임의 포트를 열고, 앱은 백엔드가 준비됐다는 응답을 받은 뒤 그 주소로 장치를 연결한다. 준비 응답의 컨트롤러 종류와 주소도 확인한다. 단순히 프로세스가 실행됐다는 사실만으로 연결 성공을 표시하지 않도록 한 것이다.

이 구조에서 Windows ARM64 지원은 UI 프로그램 하나를 ARM64로 빌드하는 문제보다 범위가 넓다. 앱, Go 백엔드, 장치를 연결할 드라이버가 함께 동작해야 실제 입력 경로가 만들어진다.

## 마우스는 스틱과 같은 입력이 아니다

WASD를 왼쪽 스틱에 대응시키는 일부터 작은 차이가 생긴다. W와 D를 동시에 누르면 가로·세로 성분이 모두 최대가 된다. 두 값을 그대로 사용하면 대각선 벡터가 한 축만 입력할 때보다 길어진다. PXPad는 길이가 1을 넘는 방향 벡터를 정규화해 대각선에서도 스틱의 범위를 유지한다.

마우스는 더 까다롭다. 마우스가 보내는 것은 일정 시간 동안의 상대 이동량이다. 반면 스틱은 특정 방향으로 얼마나 기울어져 있는지를 나타낸다. 이동량을 그대로 스틱 값으로 쓰면, 입력을 모으는 시간 간격에 따라 같은 움직임도 다르게 해석될 수 있다.

그래서 Raw Input으로 받은 상대 이동량을 모은 뒤, 처리 간격으로 나누어 속도에 해당하는 값으로 환산하고 감도를 적용했다. 그다음 시간 간격을 반영하는 지수 평활화를 거쳐 값이 급격히 바뀌는 정도를 조절한다. 작은 움직임이 게임의 스틱 데드존 안에 묻히지 않도록 출력 크기를 보정하는 설정도 두었다.

여기에는 서로 맞물리는 조정이 있다. 평활화를 강하게 하면 값은 부드러워지지만 반응이 늦게 느껴질 수 있다. 데드존 보정을 크게 하면 작은 이동도 전달하기 쉬워지지만 시작 움직임이 거칠어질 수 있다. 감도만 높여서 모든 게임에 맞는 조작감을 얻기는 어렵기 때문에 각각을 조정할 수 있게 했다.

멈추는 쪽도 별도로 처리했다. 마우스의 새 이동이 일정 시간 들어오지 않으면 평활화 상태를 0으로 되돌린다. 현재 구현의 기준은 50ms다. 이전 움직임의 잔여 값이 계속 스틱 입력으로 남는 것을 줄이려는 처리다.

이렇게 변환해도 게임이 정한 스틱의 최대 회전 속도를 넘어설 수는 없다. PXPad의 마우스 조작은 게임패드 입력을 만드는 방식이며, PC 게임이 마우스를 직접 받아들이는 조작과 같은 결과를 보장하지 않는다.

## 입력을 보내는 만큼, 끊는 방법도 필요했다

입력 프로그램에서 특히 신경 쓸 상황은 키를 누르는 순간만이 아니다. 이동 키를 누른 채 다른 창으로 전환하거나, 입력을 전달하던 프로그램이 중간에 멈출 수도 있다. 이런 상태에서 마지막 패드 값이 유지되면 사용자는 더 이상 조작하지 않는데 캐릭터가 계속 움직일 수 있다.

PXPad는 가상 패드 연결과 입력 활성화를 분리했다. 패드가 연결되어 있어도 바로 키보드와 마우스를 전달하지 않는다. 대상 창에서 F8을 눌러 시작하고, 다시 F8을 누르면 해제한다. 창 포커스가 바뀌거나 입력 처리·UI 응답이 지연되는 경우에도 입력을 해제하도록 했다. 설정 변경 역시 기존 입력을 중지한 뒤 적용한다.

백엔드에도 별도의 중단 조건을 넣었다. 입력 프레임이 250ms 이상 오래됐다고 판단하면 패드 상태를 중립으로 돌린다. 감시는 별도 주기로 동작하므로 이 숫자가 모든 상황에서 정확히 250ms 안에 복구된다는 실시간 보장은 아니다. 핵심은 UI 쪽 해제 처리에만 의존하지 않고, 입력을 받는 쪽에서도 오래된 값을 폐기한다는 점이다.

처리가 잠시 밀렸을 때에는 오래된 입력을 모두 차례대로 재생하기보다 최신 상태를 남기도록 했다. 게임 조작에서는 지나간 입력을 늦게 따라가는 것보다 지금의 키와 스틱 상태를 전달하는 것이 중요하기 때문이다.

프로세스 종료도 같은 문제의 연장선이다. 부모 앱과 백엔드를 Windows Job Object로 묶고, 입력 파이프가 닫히면 백엔드가 종료되는 경로를 두었다. 가상 장치를 해제할 때에는 자신이 연결한 포트인지 확인한다. 앱이 닫힌 뒤 백엔드만 남거나, 정리 과정에서 다른 USB/IP 장치를 건드리지 않도록 소유 관계를 관리하는 방식이다.

## 두 컨트롤러를 같은 화면에서 다루기

PS Remote Play용 DualSense와 Xbox 클라우드용 XInput은 버튼의 이름만 다른 것이 아니다. 출력 상태의 축 범위와 방향, 버튼 표현도 맞춰야 한다. PXPad는 입력 매핑을 공통 상태로 만든 뒤 백엔드에서 각 장치의 상태로 바꾼다. Xbox 쪽에서는 스틱 축을 해당 범위로 확장하고 Y축 방향을 변환하며, 공통 버튼을 Xbox 버튼에 대응시킨다.

이렇게 하면 사용자의 키 설정과 마우스 처리를 모드마다 별도로 반복하지 않아도 된다. 대신 모드를 바꿀 때에는 기존 패드와 입력을 해제하고 새 패드를 연결해야 한다. 화면의 모드 이름만 바뀌고 이전 장치가 계속 동작하는 상태를 피하기 위한 흐름이다.

실제 사용을 위한 설정도 함께 다뤘다. 기본 키 배치를 바꾸더라도 사용자가 직접 정한 매핑은 보존하고, 이전 기본값을 그대로 쓰는 설정만 새 기본 배치로 갱신한다. 트레이 실행과 입력 상태 오버레이는 설정 창을 계속 열어 두지 않아도 연결과 입력 상태를 확인하기 위한 기능이다.

다만 Xbox 모드의 대상 판별에는 아직 경계가 있다. 현재는 브라우저 프로세스를 기준으로 동작하고, 게임 탭과 다른 탭을 구분하지 않는다. 따라서 탭을 전환하기 전에 입력을 해제해야 한다. 창을 구분하는 것과 브라우저 안의 게임 화면을 구분하는 것은 별도의 문제로 남아 있다.

## 가상 패드가 연결된 다음에 확인할 것

검증도 입력 경로를 따라 나누었다. 매핑 로직에서는 키와 마우스가 어떤 패드 상태를 만드는지 확인한다. 백엔드 검사에서는 컨트롤러 보고서와 오래된 입력의 판정, 잘못된 입력을 받았을 때의 종료를 확인한다. 프로세스 통합 검사는 USB/IP 연결 절차와 장치 종류, 부모 파이프가 닫힌 뒤 리스너가 정리되는지까지 다룬다.

Windows 개발 환경의 기록에는 XInput 버튼·방향키·트리거·스틱 입력, 중립 복귀와 자기 장치 해제를 확인한 결과가 남아 있다. 이 글을 정리한 Mac에서는 해당 Windows 검사를 재실행하지 않았다.

남은 단계는 실제 게임이다. **공식 PS Remote Play의 콘솔 게임과 Xbox 클라우드 게임 플레이는 아직 검증하지 않았다.** Windows가 가상 장치를 받아들였다고 해서 모든 게임의 조작감과 호환성까지 확인된 것은 아니다. 터치 스와이프·자이로·진동 피드백도 현재 지원 범위에 포함하지 않았다.

다음에는 실제 플레이에서 입력 시작·해제와 창 전환이 예상대로 동작하는지, 게임별로 감도·데드존·평활화를 어떻게 조정해야 하는지를 확인해야 한다. PXPad에서 구현한 것은 키를 바꾸는 화면뿐 아니라, 입력을 가상 장치까지 전달하고 문제가 생겼을 때 그 입력을 거두는 경로다. 이제 그 경로가 실제 플레이에서도 자연스럽게 이어지는지 확인하는 일이 남아 있다.
