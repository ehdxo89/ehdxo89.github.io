## 학습 범위

반복 작업을 자동화하기 전에 무엇을 정해야 하는지 정리했다. 알렉스의 공개 가이드를 참고하고, 자료 정리 작업에 적용할 실습안을 구성했다.

원문은 반복 업무 하나를 정한 뒤 수동 실행으로 결과를 확인하고, 절차를 재사용 가능한 형태로 만든 다음 예약을 붙이는 순서를 제안한다. **실행 횟수보다 중요한 것은 결과를 판단할 기준이다.** 이 문장은 해당 제안을 읽고 정리한 학습 관점이다. [참고: AI Native 시작 가이드](https://www.careerhackeralex.com/sharings/ai-native-faq)

## 작업 하나로 범위 좁히기

실습 주제는 ‘선택한 학습 자료 3건을 검토 목록으로 정리하기’로 잡는다. 채널 전체 수집이나 공개 발행까지 한 번에 묶지 않는다.

아래 기준은 이 글에서 만든 연습용 설계다. 현재 수집 시스템의 구현 명세나 실행 결과는 아니다.

- **입력:** 원문 주소, 확인한 본문, 확인 날짜.
- **출력:** 자료별 주제, 핵심 내용, 확인 범위, 미확인 항목.
- **완료:** 각 요약이 어느 원문에 근거했는지 추적 가능.
- **실패:** 원문 접근 불가, 본문 누락, 제목과 내용 불일치.
- **공개:** 작성 결과를 검토한 뒤 별도로 결정.

원문을 읽지 못했을 때 제목만으로 내용을 채우면 정상 결과와 실패 결과가 섞인다. 이 실습에서는 요약 대신 실패 상태를 남긴다.

## 입력을 바꿔서 확인하기

같은 입력을 반복하는 것만으로 예외 처리를 확인하기는 어렵다. 다음 세 가지 입력을 준비한다.

1. 본문이 있는 자료. 핵심 내용과 출처가 연결되는지 확인.
2. 접근할 수 없는 자료. 요약을 만들지 않고 실패로 남기는지 확인.
3. 같은 주소가 두 번 들어온 자료. 중복 처리 기준이 유지되는지 확인.

다음은 결과를 기록할 양식이다. 수치는 실행 후 직접 채운다.

```text
실행 날짜:
입력 자료:
예상 결과:
실제 결과:
원문 확인 범위:
수정한 내용:
재검증 결과:
```

출력이 그럴듯한지보다, 정한 조건을 지켰는지 확인한다. 실패 사례도 다음 실행의 검증 입력으로 보관한다.

## 재사용과 예약 분리

여러 입력에서 절차가 안정되면 공통 단계를 정리한다. 요청마다 달라지는 값과 항상 지켜야 할 규칙을 나누는 것이 먼저다.

- 달라지는 값: 자료 주소, 조사 기간, 출력 위치.
- 공통 규칙: 출처 표시, 확인 범위 구분, 실패 상태 보존.
- 실행 조건: 선행 작업 완료 여부, 같은 작업의 실행 여부.
- 중단 조건: 자료 접근 실패, 출력 저장 실패.

예약은 실행 시점을 정할 뿐, 결과의 정확성을 보장하지 않는다. 실패한 실행을 ‘새 자료 없음’으로 처리하지 않도록 설계한다.

## 실습 완료 기준

정상·접근 실패·중복 입력에서 기대한 상태가 나오는지 확인한다. 결과를 저장한 뒤에도 출처와 실패 이유를 다시 읽을 수 있어야 한다.

이 글의 실습은 **설계 단계**다. 실행 시간, 비용 절감, 자동화 성공률은 아직 측정하지 않았다.
