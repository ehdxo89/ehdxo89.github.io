## 구축 목적

개인 프로젝트의 요청과 개발 작업을 Slack에서 관리한다. Codex는 연결된 프로젝트에서 구현하고 검증한다.

관리할 대상은 세 가지다. **프로젝트, 작업 대화, 검증 결과.** 이 글은 현재 운영 규칙을 정리한 기록이다. 실시간 실행 상태는 아니다.

## 대화 범위

- **DM:** 전체 프로젝트 관리와 작업 전달.
- **채널:** 연결된 프로젝트의 요청과 논의.
- **스레드:** 개별 작업. 후속 요청과 결과도 같은 스레드에 기록.

메뉴 수정과 API 설계는 별도 스레드에서 진행한다. 메뉴 수정의 추가 요청은 기존 스레드에서 이어간다.

```text
project-channel
  ├─ thread-A → navigation-task
  └─ thread-B → api-design-task
```

브리지는 채널·프로젝트와 스레드·작업 세션의 연결을 관리한다. 스레드가 달라도 같은 파일을 수정한다면 작업 조정이 필요하다. 다른 작업자의 변경은 보존한다.

## 완료 조건

구현 전에 입력과 기대 결과를 정한다. 모바일 메뉴 작업의 예시는 다음과 같다.

1. 작은 화면에서 메뉴 버튼 표시.
2. 메뉴 열기와 링크 이동 정상 동작.
3. 키보드 조작 가능.
4. 기존 데스크톱 메뉴 정상 동작.

확인 항목은 작업에 맞게 정한다. 프로젝트 지침과 기존 변경부터 확인한다.

## 구현·검증·전달

- **구현:** 수정한 파일과 동작.
- **실행:** 실제 프로그램이나 페이지 실행 여부.
- **검증:** 확인한 조건과 통과·실패 결과.
- **전달:** 결과 전송 여부. 사용자 열람 여부와는 별개.

검증 실패 시 원인을 기록하고 수정한다. 같은 조건으로 다시 확인한다. 미확인 결과는 완료로 처리하지 않는다. 공개 배포·삭제는 별도 승인 후 진행한다.

## 웹 시연 범위

[작업 흐름 시연](/projects/slack-codex/#demo)은 접수·맥락 확인·검증·보고의 네 단계로 구성했다. 정상 흐름과 검증 실패 흐름을 선택할 수 있다.

**미리 작성한 메시지를 사용하는 모의 시연이다.** 입력은 브라우저 화면에만 표시한다. Slack 전송, Codex 실행, 파일 변경, AI 호출은 없다.

화면 크기별 표시, 키보드 조작, 빈 입력, HTML 문자열 표시를 검증했다. 웹 시연의 검증 결과이며 실제 연동 시스템 전체의 검증 결과는 아니다. 실제 실행 영상과 시스템 검증은 별도 작업으로 남아 있다.

## 기록 관리

- **Notion:** 조사, 설계 초안, 진행 기록, 결정 이유.
- **GitHub:** 소스와 변경 이력.
- **홈페이지:** 공개 학습 글과 프로젝트 소개.

내부 문서에서 공개 가능한 설명만 정리한다. 계정 정보, 인증정보, 내부 채널 주소는 제외한다.

다음 작업은 실제 요청부터 결과까지의 검증 사례 정리다. 측정하지 않은 생산성 수치는 사용하지 않는다.
